这里记录每次发布给 Plexus 使用者带来的变化。通信协议单独管理版本，更新频率也低得多，详见 [协议](/zh/protocol/)。

## 0.9.1 — 连接你日常使用、已登录的 Chrome {#_0-9-1——够到你真正登录着的那个浏览器}

`attach` 现在能连接你日常使用的 Chrome，也多了第三种连接方式。

- **支持 `chrome://inspect` 远程调试开关。** 从 Chrome 136 起，Chrome 会拒绝用于默认用户配置的 `--remote-debugging-port` 参数。该开关提供另一种连接接口，是**通过原生 DevTools 接入默认用户配置的唯一途径**；它与传统参数提供的接口现已共用同一连接层。
- **Chrome 扩展成为第三种传输方式。** 只需**在安装时授权一次**，不用每次连接都授权，也能用于你平时使用的配置文件。扩展只负责传输：允许列表、审批和审计仍由网关管理，页面无法干预。
- **点击和输入改用真实输入事件。** 忽略直接 DOM 写入的自定义表单控件和富文本编辑器现在也能收到智能体的输入；目标被其他元素遮挡时，点击会被拒绝。
- 标签页在被列出之前就已过滤：一个开着 25 个标签页的浏览器里，只有已授权域名上的那些会出现。

## 0.9.0 — 浏览器控制 {#_0-9-0——browser-control}

**新增浏览器控制来源。** 它属于 execute 类，通过 DevTools Protocol 操作真实的 Chrome，支持导航、读取、点击、输入、截图和上传，不依赖 Puppeteer 或 Playwright，也无需下载浏览器。

- **所有者要决定的是用哪个浏览器**：使用全新、空白、未登录任何账号的配置文件，还是自己已经登录的浏览器。**这个选择决定了操作可能影响的范围**，其他都是细节。
- **域名允许列表由所有者控制。** 检查以实际目标 URL 为准，每次操作前都会重新核对。Chrome 的连接许可针对浏览器，并不限定可访问的网站，因此还需要单独的域名限制。
- **页面内的操作全部开放**，包括任意 JavaScript 和原始的页面级 CDP，范围限于代理本来就有权访问的页面。在这些页面内，点击和输入已经让代理具备用户的全部操作能力。浏览器全局的 CDP 则不开放，这条边界让允许列表的限制仍然有效。
- **只能上传你指定的一个目录内的文件**；指定目录之前，所有上传都会被拒绝。

见[暴露一个 source](/zh/guide/first-party-sources#browser-control)。

## 0.8.0 — 耗时调用支持异步，控制台新增活动摘要 {#_0-8-0——长调用不再堵着-控制台说得更多}

- **异步 invoke 句柄。** 耗时数分钟的 capability 立即返回一个句柄，而不是占着连接；agent 在结果就绪时来取。
- 控制台新增 **Activity 概览条**——一眼看清最近发生了什么。
- **沙箱运行的失败输出在抵达 agent 之前会被脱敏。**
- **完善智能体协议。** 拒绝响应现在包含足够的信息，智能体可据此修正请求，无需猜测。

## 0.7.0——首个公开发布

首次公开发布时，信任模型已确定，本机已有足够多的真实来源可用，让接入智能体有了实际用途。

- **扩充个人数据来源支持。** 在已有的 Calendar 和 Reminders 之外，第一方来源新增 Apple Notes、Mail、Contacts、Photos 和 Shortcuts；浏览器标签页、书签和历史记录仅支持读取，Obsidian 支持搜索和追加。
- **智能体只看到已授权的部分。** 发现接口不再返回完整目录，只展示**所有者授予该智能体的范围**；范围外的请求直接拒绝，不再进入审批队列。
- **有副作用的能力默认逐次审批。** 此版本中，连接时选择 `write` 或 `execute` 不再自动获得持续授权，每次调用都需单独批准。持续授权默认关闭，需按能力主动开启，并经过两次确认。
- **无法确认会话有效时，拒绝访问。** 撤销授权会立即彻底停止相应访问。
- **提供四种智能体安装方式。** 其中一种可在上下文中完成，适用于既不能访问文件系统、也不能使用 shell 的智能体；快速入门指南涵盖完整设置流程。
- **编码类 agent 使用它们自己的原生沙箱**，而不是在外面再套一层。

## 0.7 之前

一路走来，每个阶段一段话。

- **0.6.0-rc.1** — 首个公开发布候选版本：重新设计桌面端和运行时，统一授权与信任模型；新增按 Connector → Source → Capability 组织的 *What I expose* 视图，接入首批 Apple 来源，并提供各来源的健康状态。
- **0.4.0** — 可通过控制台或 CLI **实时添加、启用、重新配置和移除能力来源**，无需标志参数，也无需重启。重新配置某个来源的安全相关设置时，会清除该来源的授权。
- **0.3.x** — 新增 Claude Code 和 Codex 集成，主流编程智能体可使用 Plexus 提供的能力；通过 Obsidian 自身的 Local REST API，支持读取和**写入** Obsidian 内容。
- **0.2.x** — 发布 manifest 规范，支持用户编写技能和工作流；提供 macOS 首次使用流程，引导用户完成从安装到连接智能体的过程。
- **0.1.x** — 实现网关和 M0 协议契约，并确立此后所有版本的基础原则：**默认由人决定是否授权**，智能体不能自行授予自己写入或执行权限。
